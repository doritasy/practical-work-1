\# Практическая работа №1



\## Описание



Прототип веб-приложения, в котором данные хранятся в памяти (не на диске).

Реализована модель слоя доступа к данным и REPL для работы с ней.



Вариант №14. ER-диаграмма содержит три сущности: Participant, Command, Reply.Между ними связи:

команда ссылается на участника, а ответ — на команду.



\## Требования



\- Python 3.10+



\## Как запустить



На Windows достаточно запустить `run.bat`.



На Linux или Mac:



```bash

python src/main.py

```



\## Как пользоваться



После запуска открывается консоль (REPL), куда можно вводить команды. Доступные команды:

\- `create\_participant` — создаёт нового участника (спрашивает ip и описание)

\- `get\_participants` — показывает всех участников

\- `get\_participant\_by\_id` — ищет участника по id

\- `create\_command` — создаёт команду (спрашивает id участника и описание)

\- `get\_commands` — показывает все команды

\- `get\_command\_by\_id` — ищет команду по id

\- `create\_reply` — создаёт ответ (спрашивает id команды и текст ответа)

\- `get\_replies` — показывает все ответы

\- `get\_reply\_by\_id` — ищет ответ по id

\- `get\_replies\_with\_participant` — сложный запрос: соединяет все три таблицы и фильтрует по времени

\- `Выход` — завершает программу



\## Про сущности



\*\*Participant\*\* — участник. Хранит `ip` и `description`.



\*\*Command\*\* — команда. Хранит `participant` (id участника), `created`

(время создания) и `description`.



\*\*Reply\*\* — ответ. Хранит `command` (id команды) и `response`.



Данные лежат в словарях: ключ — это id записи, значение — словарь с полями.
